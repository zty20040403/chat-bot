# ADR 005：控制台、运维查询和远程执行分离

状态：采用；远程写操作、自动修复和部署必须由部署方单独配置。
作者：Kenneth。日期：2026-09-07。

## 问题

集群里既有服务器，也有同学的个人机器。一个聊天请求不能自动获得全部主机权限。
运维后端取不到数据也不等于服务器关机。网页自动更新不能打断管理员正在编辑的表单。

## 决策

1. PostgreSQL 保存权威业务状态；Alembic 管理 schema，向量和摘要属于派生索引。
2. 管理 API 输出稳定资源版本，修改记录操作者、目标和结果；React 通过 SSE 合并更新，
   表单和下拉框的本地状态不因数据刷新被销毁。
3. 集群查询经独立控制服务访问已配置的外部 Ops HTTP 接口。按操作目录验证只读能力，
   只传必要目标，不传聊天上下文或模型密钥。
4. Worker 只领取固定计算合同；部署器只接受已经批准的精确 Git 提交及 Nix 闭包。
5. 主机身份、资源上限、服务白名单、授权期限来自部署配置，而不是模型自由填写。
6. 用 `fresh`、`stale`、`unavailable` 区分观测质量，保留来源和确切时间；失联不是停机证据。
7. NixOS 用独立服务和凭据隔离进程。聊天服务的 Docker 权限也不能转交给任务容器。

## 实现位置

`src/plugins/ai_chat/admin.py` 与 `admin-ui/` 是管理接口和控制台。
`src/cluster_control/adapters/ops.py` 是外部操作目录适配器，不是自建通用 SSH 后门。
`src/cluster_worker/`、`src/cluster_deployer/` 承担不同执行职责。
`src/bot_storage/`、`migrations/`、`nix/` 提供存储迁移和可复现部署。

## 取舍

外部运维接口继续复用，产品名称和内部编排独立。运维接口的协议并非 gaoji 私有协议，
不能因为改品牌就假装拥有上游实现。
不让网页直接执行任意命令，不在每台节点复制全部聊天、浏览器和媒体依赖。
代价是配置及鉴权链路较多；未配置的能力必须显示不可用，不能用高权限 shell 自动绕过。

## 回归检查

验证接口 401/403、目录版本不支持、超时和旧缓存的展示；检查并发修改的版本冲突及审计。
每次系统切换前获取最新部署仓库，查看共享主机的变更范围，保留已有服务与数据路径。
数据库热备是部署拓扑，不是应用天然高可用；机器人进程所在主机故障仍会中断服务。
