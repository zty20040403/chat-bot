# ADR 001：在平台边界统一消息和身份

状态：采用。作者：Kenneth。日期：2026-09-07。

## 问题

QQ、Matrix 和 iMessage 的消息编号、引用、图片和用户身份并不相同。把这些差异交给
每一个工具处理，会产生“同一条消息保存两份”“引用错人”“把图片当文本”等问题。
平台接入可用也不代表所有平台都具备同样的发送能力。

## 决策

1. 入口适配器把原始事件解码为 `MessageBody`，再交给消息账本。
2. 来源平台和原生消息 ID 用于去重；内部使用规范 `msg#`、principal 和 conversation scope。
3. 引用、提及、文件、图片、分享卡片保留结构，不仅保存一段拼接文本。
4. 工具返回规范内容；出口按目标平台能力降低为原生消息或可读 fallback。
5. 每次数据读取仍要检查真实会话权限，知道一个句柄不等于获准读取它。

群公共消息可以被本群成员用于理解话题，个人记忆则绑定本人。表情库是单独管理的共享资源，
只有明确审核允许共享的表情才能跨群使用，不能把这项例外扩大成原始群聊互通。

## 实现位置

- `message_ir.py`：内部消息节点及规范编码。
- `onebot_codec.py`、`bridges.py`：平台解码、来源去重与桥接。
- `ledger.py`、`conversation_scope.py`：消息事实和真实会话范围。
- `message_lowering.py`、`onebot_delivery.py`：能力降级和实际发送。

以上 Python 文件位于 `src/plugins/ai_chat/`。

## 取舍

不让所有平台都伪装成 QQ：能减少入口代码，但会丢失能力差异。
不直接把平台 ID 交给模型当授权凭据：模型可以选择对象，不能扩张访问范围。
代价是需要维护规范节点及各平台降级测试；未知节点必须提供安全文字表示。

## 回归检查

重复接收同一事件不能新增第二条事实；引用和提及应指向正确 principal；猜测另一个群的
`msg#` 必须被拒绝；不支持的媒体不能悄悄变成一次成功投递。
