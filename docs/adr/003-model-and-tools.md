# ADR 003：模型提出动作，宿主执行授权

状态：采用。作者：Kenneth。日期：2026-09-07。

## 问题

同一机器人需要切换不同模型；工具又可以发送消息、创建文件甚至申请远程操作。
供应商协议、模型输出和用户权限若混在同一个循环里，切模型就可能改变安全边界。

## 决策

1. 用不可变 ModelProfile 描述模型、协议、密钥来源、推理配置、能力和超时。
2. Gateway 适配供应商协议，对 Agent 返回统一工具调用及用量信息。
3. 每轮记录期望模型、实际模型和降级原因，不把静默换模型显示为原模型成功。
4. 工具目录由宿主生成。调用前检查 schema、scope、风险、权限和批准状态。
5. 对副作用声明幂等语义；发生超时而结果不明时，不能把“不知道”当成“未执行”。
6. 限制循环、重复调用及总执行预算。可接管任务持久化后再交给后台执行。

网页、文件、工具输出只是输入资料，不是新的系统指令。模型输出的 `approved=true`
或自称管理员，不构成执行许可。

## 实现位置

`src/plugins/ai_chat/model_catalog.py`、`llm_gateway.py`、`deepseek.py` 分别负责 profile、
协议和现有 Agent loop。`deepseek.py` 是仍保留的模块文件名，不表示只能调用该供应商。
`tool_policy.py`、`tool_executor.py`、`turn_journal.py` 负责验证、执行和可回放记录。
`runtime.py` 统一装配资源，`lifecycle.py` 管理后台任务生命周期。

## 取舍

保留可观测的 ReAct 工具循环，不为了名称复杂而引入完整动态计划语言。
不允许模型直接传 URL、token 或 shell 取代受限运维工具。通用 shell 只存在于已授权沙盒边界内。
代价是每增加一个工具都要补齐合同、错误分类和测试，不能只添加一段模型提示词。

## 回归检查

工具参数不合法应在产生副作用前拒绝；切换协议不丢失 tool-call 对应关系；结果不明的
非幂等操作不能自动重放；密钥不出现在模型回复、repr、管理接口或日志中。
