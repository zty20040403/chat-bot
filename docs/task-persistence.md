# 后台任务持久化与恢复

## 用户看到的变化

后台 Sub-Agent 任务不会再因为服务器命令仍在运行，就提前报告“部分完成”。
控制台显示“等待外部结果”，任务保留原目标、独立 Agent 上下文、已完成步骤和远程作业编号。
结果返回后，宿主重新领取任务，继续未完成的步骤，验收后把最终结论写进消息投递队列。
等待过程中不反复调用 LLM。

这套恢复适用于已提交到持久队列的 Sub-Agent 任务。普通即时聊天不自动升级成长任务。

## 持久记录

| 内容 | 保存位置 | 恢复方式 |
| --- | --- | --- |
| 任务目标、原消息、用户、群、期限、修订号 | subagent_tasks / subagent_controls | 从原始身份恢复工具环境，不借用其他群或账号 |
| 已完成步骤、各 Agent 对话和工具结果 | subagent_runs / subagent_sessions | 成功步骤不重跑；继续未完成步骤 |
| 调度所有权 | durable_jobs | 租约到期后接管；旧 Worker 失去写入权 |
| 外部请求意图、幂等键、作业句柄与结果 | subagent_external_calls | 有句柄则查询；提交回执丢失则使用同一个幂等键核对/重试 |
| 最终回复 | deliveries / delivery_attempts | 任务完成后独立入队，QQ 恢复连接再投递 |

生产数据保存到 PostgreSQL。SQLite 只用于隔离测试和已有迁移工具。
本次需要 Alembic `0027_external_continuations`；迁移保留已有任务和消息，不重发历史终态任务。

## 执行顺序

1. 先保存模型提出的工具调用，再执行副作用。
2. Fleet 请求先保存宿主生成的幂等键，再发送到控制面。写操作仍经过原任务授权。
3. 保存远程句柄和工具回执。异步作业未结束时，当前 Agent 进入等待状态。
4. 同一工作流中的独立步骤仍可完成；依赖等待结果的步骤不会提前运行。
5. 等待任务释放 Worker 名额，通常 15 秒后核对一次远程状态。QQ 断线通常 30 秒后再检查。
6. 重启后只接管当前修订的任务。得到最终远程结果后修复工具对话记录并继续。
7. 最终答复入队键固定为 `subagent-final:<任务>:<修订>`。入队之后再写标记，因此两步之间重启不会漏发或重复建立投递。
8. 发现回执丢失时，从原账号、原群的最近消息中匹配完整正文和引用编号；匹配成功才确认送达。

任务保留总期限，重启不会刷新期限。正常等待、QQ 离线和检查点任务的租约丢失不消耗失败重试额度；真正执行错误仍有有限重试。
取消或超时会停止后续步骤并发送终态说明，但不把“停止等待”伪装成“远程命令已经取消”。

## 巡检任务的证据交接

- 明确修订后，续跑检查只检查本次选中步骤的新执行记录；未选中的步骤和本轮未确认的副作用仍受原有保护。其他步骤等待时，不能把已经成功的步骤改回失败。
- 补查服务状态不会丢掉此前的磁盘、内存等实测数据。旧观测通过 `read_agent_result(section="previous_evidence")` 单独读取，带来源步骤和时间；冲突以更新的观测为准，旧文件不会因此重新进入交付队列。
- `jobs.logs` 的 Base64 输出由客户端解码为文本，保留字节分页游标与截断标记。模型应先读取已有作业输出，不应因看不懂编码就重新全盘扫描。
- 控制面参数错误返回可定位的字段信息，便于修正请求；不把认证信息或原始敏感输入交给模型。

只读巡检与清理授权是两回事。目录大小不等于可释放空间；没有核实对象归属、在用状态与影响，不执行清理，也不申请笼统的全盘删除授权。

## 不能保证的事情

- 数据库或原工作区被删除后，不能凭空恢复数据；这不是数据库备份的替代品。
- QQ 没有可由客户端指定的端到端幂等消息编号，因此不能承诺绝对 exactly-once。
- QQ 若已收到消息但回执和可核对历史都不可用，投递保留为 `ambiguous`，不盲目重复发送。私聊仍依赖回执或自发消息事件，不使用群历史接口核对。
- 未接入持久回执的不可重复操作若在执行中崩溃，仍停止自动重放并说明结果未知，不能为了“继续”而重复删除、上传或执行服务器命令。
- 模型不可用、远端拒绝执行、权限撤销、任务期限耗尽等真实失败，不会被伪装成完成。
- 临时沙盒和文件继续遵循原有清理策略，不因为持久任务无限保留。

## 验证

`tests/test_external_continuations.py` 使用隔离数据库和模拟远端，覆盖等待后重启、提交回执丢失、重复接管、只恢复未完成步骤、离线、取消、期限、任务隔离和最终消息核对。
不会在测试中调用生产模型、执行真实服务器命令或向群里发消息。

上线后可提交一次只读检查任务，在控制台看到“等待外部结果”时重启 Bot，再核对同一任务号、同一远程作业号和唯一的最终投递。
不要拿删除或重启服务器作为首个恢复演练。
